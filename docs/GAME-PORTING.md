# Porting the game code (`crates/pg-game`)

`pg-game` is the original's game layer — `PocketGodViewController`, the managers, the personas
and every logic class — rebuilt on `pg-engine`. Its skeleton (modules, components, `Class`
constants, dispatchers, one stub per method) is generated by `tools/port/gen_game.py`; porting a
class means filling in its stubs from the decompiled original. This guide is the contract every
part of the crate follows. `docs/ARCHITECTURE.md` has the overall design.

## 1. Sources

- **Decompiled code (the source of truth).** `tmp/re/decomp/game/<Class>.c` and
  `<Class>+<Category>.c`, one function per `// ==== <address> <Class>::<selector>` header. Every
  stub's doc comment carries the address: `grep -rn '100091f78' tmp/re/decomp/game` finds it.
  Free functions (`FUN_…`) and everything else are in `tmp/re/decomp_raw/all.c`
  (`//==== FUNCTION <address> <name>`; index in `tmp/re/decomp_raw/index.tsv`).
  `docs/re/README.md` explains how to read Ghidra's output (ivar offsets, `_objc_msgSend`,
  blocks, C++ containers).
- **Values in the binary.** `python3 tools/re/resolve.py <address>` resolves globals, C strings,
  `CFString`s and class refs; `--floats N`, `--u64 N` and `--hexfloat` read tables. Class metadata
  (ivars, type encodings) is in `tmp/re/classes.json`.
- **Specs.** `docs/re/controller.md`, `pygmy.md`, `logic-catalog.md` and `managers-platform.md`
  describe the game classes; `logic.md`, `sequences.md`, `timelines.md`, `rendering.md`,
  `audio-prefs-text.md`, `struct-xml.md` and `textures.md` describe the engine they run on. They
  explain; where one disagrees with the decompiled code, the code wins (say so in your report).
- **The engine.** `docs/ENGINE-API.md` lists every public engine item with the selector it ports:
  `grep -n 'setBehavior:' docs/ENGINE-API.md`. Source: `crates/pg-engine/src`.
- **Data tables.** `pg_assets::data::<table>::load()` deserializes `assets/data/<table>.json`
  (episodes, skin packs, dance beats, Konkey Dong levels, links, debug items, logic objects, …);
  `pg_assets::file("xml/story.xml")` and `"xml/news.xml"` are the bundled XML. Parse a table once
  and keep it (a resource or a `std::sync::OnceLock`), not on every call.

## 2. The skeleton

- **Modules.** One module per class (paths in `tools/port/game-layout.json`). Big classes are split
  into part files re-exported by the class module: `PocketGodViewController` is `crate::controller`,
  `PygmyLogic` is `crate::pygmy`, each manager is `crate::managers::<name>`; `crate::pygmy::fall`
  works whichever part defines `fall`.
- **Ivars.** One component per class holding its own ivars (`BirdLogic`); a split class has one
  per part (`PygmyPygmyCoreFrame`, …) plus `insert_components` in its module. Field comments name
  the original ivar and its type encoding. An object of class `BirdLogic` carries `BcLogic`,
  `SpriteLogic` and `BirdLogic`.
- **`Class` constants.** `pub const BIRD_LOGIC: Class` is the class's vtable for the engine's
  dynamically dispatched slots (`onGameFrame:`, touches, `setBehavior:`, `shutdown`, …), built from
  its superclass's with struct-update syntax. The generated `sequence_item` (the class's `name:::`
  sequence handlers) and `perform` (timeline frame actions) dispatchers are complete.
- **Stubs.** One `pub fn` per method with the doc line `` /// `-[Class selector]` @ 0x… `` — keep
  that line, it is how methods are found. `seq_<name>(world, this, call) -> ItemResult` are the
  sequence handlers. `spawn(world, display_object)` is `[[Class alloc] initWithDisplayObject:]`.
- **Shared modules.** `crate::send` (dynamic dispatch, §3), `crate::singletons::Singletons`
  (`+instance` statics), `crate::logic_table` (the logic array's slots by name),
  `crate::library_logic` (`createLogicClasses`), `crate::types` (named C structs),
  `crate::prelude` (common imports).

## 3. Object model

- **Methods** are `fn(world: &mut World, this: Entity, …)`. Read components with
  `world.obj::<T>(entity)` / `world.obj_mut::<T>(entity)` (readable panic if missing) or
  `world.get::<T>(entity)` when the object may lack it. Never hold a component borrow across a call
  that takes `world`: copy what you need into locals, release, call (ObjC re-entrancy — A calls B
  calls back into A — then stays safe).
- **alloc/init.** `alloc` zeroes every ivar, so each `init…` first inserts its own class's zeroed
  component(s) (`world.entity_mut(this).insert(BirdLogic::default())`, or `insert_components` for a
  split class), then calls the superclass initialiser
  (`crate::logic::island_core::sprite_logic::init_with_display_object(world, this, display_object)`,
  or `pg_engine::logic::init_with_display_object` for a direct `BCLogic` subclass), then does the
  rest of the original's body in order.
- **Messages.** For `[receiver selector…]`:
  1. an engine slot (`onGameFrame:`, `setBehavior:`, `shutdown`, `id`, `isSoundDisabled`,
     `applyMoveXPos:moveYPos:`, the `touch…:allTouches:` family, `onButtonPress:touch:` …,
     `closeScreenNow`, `drawOpenGL:`, `hibernate`, `textureDef` …) goes through the engine's
     dispatching function (`pg_engine::logic::set_behavior(world, logic, Some("Walk"))`), which
     follows the receiver's `Isa`;
  2. otherwise, when `crate::send::<name>` exists (several classes implement the selector) and the
     receiver's exact class is not certain — it is typed `id`, a protocol, a superclass, or `self`
     in a class whose subclasses override the method — use `crate::send::<name>(world, Some(receiver), …)`;
  3. otherwise call the implementing class's function directly
     (`crate::logic::ocean_birds::bird_logic::drop_food(world, bird)`).
  `[super selector]` calls the nearest ancestor's function directly. A listener protocol
  (`mBirdLogicListener`) that is always the same class (find who calls `setBirdLogicListener:` —
  usually the view controller) is a direct call to that class; otherwise `send`.
- **nil.** Messages to nil do nothing and return zero. Object references are `Option<Entity>`;
  keep the original's nil checks, and where it relies on nil messaging write the `if let` it
  implies. `send` functions take `Option<Entity>` receivers and return the zero value for nil.
- **Runtime queries.** `isKindOfClass:` → `pg_engine::object::is_kind_of(world, obj, "Class")`;
  `respondsToSelector:` → `crate::send::responds_to(world, obj, "selector:")`;
  `performSelector:` → `pg_engine::object::perform(world, obj, "selector")`.
- **Lifetime.** retain/release/autorelease vanish. An object dies only where the original's last
  owner releases it; port `dealloc` and call it there, and despawn only when nothing (a listener
  list, an array, the display tree, the logic table, a frame-listener list) can still reach the
  entity — when in doubt keep it alive (a leak is harmless, a dangling `Entity` panics). Prefer the
  engine's teardown (`pg_engine::logic::dealloc`, `pg_engine::animation::dealloc`, …) over a bare
  `despawn`.
- **Singletons.** `instance(world)` returns `Singletons.<class>` (`None` before creation); the
  class's `init` stores `Some(this)` there where the decompiled `init` writes its static
  (`DAT_1007cdc20 = self`).
- **Other statics.** A class's file-scope globals (`DAT_…` counters, caches, flags) become a
  `#[derive(Resource, Default)] pub struct <Class>Statics` in its module: read with
  `world.get_resource::<T>()` (absent means all zero), write through
  `world.get_resource_or_insert_with(T::default)`. Read-only tables in the binary become `const` or
  `static` arrays with the values `resolve.py` prints.
- **The logic array.** `DAT_1007e3030` … `DAT_1007e43e8` are the 632 slots `createLogicClasses`
  fills: `pg_engine::library::logic(world, crate::logic_table::DREAM_BUBBLE)`. Grep the address in
  `crates/pg-game/src/logic_table.rs` for the name.

## 4. Engine idioms

- **Frame listeners.** `[[BCView instance] addGameFrameListener:self]` →
  `pg_engine::view::add_game_frame_listener(world, this)`; the order comes from the class's
  `game_frame_order` (already in its `Class`).
- **The view.** `BCView`'s plain getters are fields of the `pg_engine::view::BcView` resource
  (`isWideScreen` → `wide_screen`, `accelRotDegrees` → `accel_rot_degrees`, `screenWidth`,
  `gameFrameCount`, …; the index lists every struct's fields). `startRenderLoop`,
  `stopRenderLoop`, `isRenderLoopActive` and `setDisplayLinkCount:` are `pg_engine::view`
  functions. A direct `[mView gameLoop]` before the render loop runs (`loadGame`'s three warm-up
  ticks) is `pg_engine::view::game_loop(world, dt)` with dt 1/15, 0 and 0 (see its doc).
- **Timers, clock and deferred calls.** Use the shared mechanisms; do not write new ones.
  `CFAbsoluteTimeGetCurrent()` (and `[NSDate date]` arithmetic) →
  `crate::controller::cf_absolute_time_get_current(world)` (the `WallClock` resource the app
  advances in real time). `[x performSelectorOnMainThread:sel withObject:… waitUntilDone:NO]` →
  `crate::controller::perform_selector_on_main_thread(world, x, function)`, run on the next
  main-loop pass by `fire_main_thread_calls`. The controller's own `NSTimer`s live in
  `crate::controller::run_deferred_calls`. Any other one-shot timer: a due-time field in the
  class's statics checked from its `onGameFrame:` — and say so in your report.
- **Sequences.** Handlers return `ItemResult` (0 `Pending`, 1 `Yield`, 2 `Done`, 3 `Replaced`).
  Parameters: `call.float("x")`, `call.int`, `call.bool`, `call.param` (string, `None` = nil),
  `call.list`, `call.has`; `call.first_time`, `call.delta_time`. `setBehavior:` →
  `pg_engine::logic::set_behavior`.
- **Animation.** `pg_engine::logic::play_animation_id(world, this, Some("PygmyWalkAnim"))`; the
  player entity is `pg_engine::logic::animation(world, this)`.
- **Display objects.** Plain ivar setters (`setPos:`, `setScale:`, `setVisible:` …) write the
  `pg_engine::display::DisplayObject` fields (`pg_engine::display::object_mut(world, entity).pos = …`);
  setters with side effects have engine functions — grep the selector in `docs/ENGINE-API.md`
  before writing a field. Groups, markers, models, texts and gradients live in
  `pg_engine::display::*`; registries in `pg_engine::library`.
- **Sound.** `pg_engine::sound` (`play_sound(world, "Id")`, loops, mute, vibrate).
- **Random numbers.** `world.resource_mut::<Random>()`: `arc4random()`, `arc4random_mod(n)`
  (`arc4random() % n` with u32 semantics), `random()`. Keep the original's call sites and moduli.
- **Preferences and saves.** `pg_engine::prefs` (documents, keys, keychain).
- **Touches.** The engine routes touches to the `touch_*` slots; `pg_engine::touch` has the
  touch objects and `all_touches`.
- **Already-ported helpers.** Before porting a `FUN_…`, grep its address in `crates/pg-engine`:
  `FUN_1001a15d4` is `math::length3`, `FUN_1001a157c` `math::normalize3`, `FUN_10013f8cc` …
  `FUN_10013fc94` are `GlContext` state calls, `FUN_100038d68`/`FUN_100038b68`
  `texture::load_atlas`, `FUN_100038648` `texture::patch_atlas`, `FUN_100038f24`
  `texture::copy_texture_def`.

## 5. C and Objective-C details

- **Types.** `float` f32; `double` and `CGFloat` f64 (arm64); `int` i32; `NSInteger`/`long` i64;
  `unsigned` u32; `BOOL` bool; `NSString *` `String`/`&str` (`Option<String>` when nil matters);
  `NSArray`/`NSMutableArray`/`std::vector`/`std::list` `Vec`; `NSDictionary` `HashMap` (if the
  original iterates one and the order is observable, say so); `NSNumber` the number; vec4 structs
  `Vec4`. The stubs' types come from the type encodings; keep them.
- **Arithmetic.** Compute in the original's precision (f32 stays f32), keep integer division,
  truncating casts, unsigned wrap-around and the original's operation order. Do not fix bugs;
  mark deliberate ones `// Original bug, kept: …`.
- **Strings.** `stringWithFormat:` → `format!` with the same output (`%d` `{}`, `%.2f` `{:.2}`,
  `%02d` `{:02}`, `%@` `{}` …). `isEqualToString:` → `==`.
- **C++ helpers.** `FUN_…`s that only grow, copy, clear or destroy `std::vector`/`std::list`
  storage become the matching `Vec` operation.
- **Logging.** `BCLog` (`FUN_1001a8b20`), `NSLog`, `printf`: debug output, drop.
- **zlib** (`compress`/`uncompress`) → `miniz_oxide::deflate::compress_to_vec_zlib` /
  `miniz_oxide::inflate::decompress_to_vec_zlib`.
- **`NSXMLParser`** → `quick_xml::Reader` driving the same delegate functions in document order.
- **Other `FUN_…`s.** Port them as private functions next to their caller, doc line
  `` /// `FUN_<address>` ``. If another unit needs the same helper, make it `pub(crate)` in the
  unit with the most callers and mention it in your report.

## 6. Platform services (`docs/re/managers-platform.md` §18)

- **In-app purchases are free.** Every product (skin packs, Fishmas, the Comic Pre-Order bonus) is
  owned from the first launch; purchase prompts never appear; the store screens still browse
  skins; restore does nothing and succeeds.
- **Removed services.** Ads (Chartboost: never shown), analytics and crash reporting (Flurry,
  Answers, Crashlytics, Fabric) do nothing.
- **Game Center.** Authentication completes at once as "not authenticated" (every listener still
  gets `onGameServerAuthenticationComplete`). Achievements and leaderboards are local records.
  Turn-based matches: no service by default — `ChallengeManager::openMatchPanel` shows "Game Center
  not available." and `IdolManager::openMatchPanel` "Multiplayer Not Available:", as on a device
  without Game Center. Port the match code faithfully anyway (match data, turns, outcomes) so a
  local match service (§18.3) can be plugged in later.
- **Network.** None. News comes from the bundled `news.xml` and `*NewsIcon` textures; never fetch.
- **URLs** → `pg_engine::platform::open_url`. **Text entry** (`UITextField`) → the
  `pg_engine::platform::TextField` resource (§13.3 rules): the controller sets its delegate and
  callbacks (`cancel` = what tapping the cancel object does, i.e. `onHideKeyboard`);
  `becomeFirstResponder`/`resignFirstResponder` are `pg_engine::platform::become_first_responder`
  / `resign_first_responder` (the latter runs `textFieldDidEndEditing:` synchronously, as UIKit
  does); `pg-ui` draws the field. **Vibration** → `pg_engine::platform::vibrate`.
  **Country code** → `pg_engine::platform::Locale`. **Loading screen** → set
  `PlatformRequests::loading_screen_hidden` where the original hides it. iOS version checks:
  constant "7" / "iOS ≥ 5" (§18.1).
- **Debug screen.** Kept, reachable only with the developer flag (§12).

## 7. Style

- Rust naming. Keep the generated names (functions, fields, components): other units call them.
- `~/.claude/CLAUDE.md`: no long method chains, no complex expressions inside call arguments,
  named intermediate values, sequential structure, blank lines between decorated fields.
- Comments: the `` /// `-[Class selector]` `` line on every ported method; otherwise only where
  behaviour is surprising. No commented-out code.
- When a file is fully implemented, remove its `#![allow(unused_variables, unused_imports)]` and
  fix the warnings it reveals.
- No `todo!()` or `unimplemented!()` may remain. If something truly cannot be ported, write the
  closest faithful behaviour, mark it `// PORT: <why>`, and list it in your report.

## 8. Working on a unit

Units (`tools/port/units.json`) own files; work happens in a private copy of the workspace and is
merged into the main tree under a lock by `tools/port/work.py`:

```
python3 tools/port/work.py setup <unit>    # create or reuse tmp/work/<unit>; prints your files
python3 tools/port/work.py check <unit>    # cargo check -p pg-game in the copy
python3 tools/port/work.py pull <unit>     # newer main-tree files into the copy (yours kept)
python3 tools/port/work.py merge <unit>    # 3-way merge your files into the main tree + type-check it
python3 tools/port/work.py merge <unit> --also <repo-relative path>…   # plus other units' files
python3 tools/port/work.py accept <unit> <path>   # see the message of an own-file conflict
```

- Edit only your own files, in the copy. Read the main tree (`/Users/danemadsen/pocket-god-rs`)
  for everything else — docs, decompiled code, other units' progress.
- **Requests from other units.** Before you start, grep `tools/port/requests.md` for your unit
  name and your classes and functions: units that finished earlier list there what they need
  from you (mostly signature fixes, see below) and how they already call you. Apply them, and
  replace the stand-ins they used at their call sites (`string_object_placeholder("…")`,
  `vector4_placeholder(…)`, `Entity::PLACEHOLDER`, …) through `merge --also`.
- **Generated types to correct.** The skeleton typed every object pointer as `Entity`, which is
  wrong for Foundation values: an `NSString` parameter is `&str` (`Option<&str>` when nil is
  possible), an `NSString` result `Option<String>` (or `&'static str` when it is always a
  literal); an `NSArray` result `Vec<Entity>`; an `NSNumber` its number; a `VECTOR4 *` parameter
  a `Vec4` (or `&mut Vec4` when the callee writes through it); `allTouches` an `&[Entity]`
  (`pg_engine::touch::all_touches`). Fix such signatures in your own files (and their callers);
  that is the expected kind of signature change.
- **Signatures and component fields are a contract.** Other units are implemented in parallel
  against the generated function signatures and ivar fields (a unit may read and write another
  part's ivars directly). Change one of yours only when the original requires it (a parameter that
  can be nil, a different return type, an argument the stub lacks, an ivar whose generated type is
  wrong); then fix every use the merge check reports — in your files, or in other units'
  already-merged files via `--also` — and list the change in your report. Never change another
  unit's signatures or fields; report what you need instead.
- If a merge fails on something outside `pg-game` (a workspace manifest being edited by the
  platform work), wait a minute and merge again; do not touch other crates.
- `merge` refuses anything that does not type-check together with the main tree and puts the main
  tree back as it was; `pull`, fix, `check`, merge again. A busy lock just means retry. Merge
  whenever your files compile cleanly (at least once at the end); merging early lets other units
  see your work.
- Shared files (`lib.rs`, `prelude.rs`, `send.rs`, `singletons.rs`, `types.rs`, `logic_table.rs`,
  module `mod.rs` files) belong to no unit: change them only through `--also`, minimally, and say
  so in your report.
